# Record layout, status, publish

## Directory

```
$WEBGPU_BENCH_ROOT/                      default ~/webgpu-bench
  rigs/<rig>.json                        machine, GPU, driver, Dawn, OS, build flags
  runs/mac-arm64/<YYYYMMDD>-<commit8>-<tag>/
    meta.json
    status.json
    e2e/<id>-<invocation>.json
    e2e/<id>-ref.json
    e2e/sched-<id>.log
    e2e/load.log
    e2e/rss.txt
    e2e/ppl.txt
    ops/perf-{1,2,3}.sql
    ops/cases.md
    ops/weights.json
    profile/<case>/{raw,cpu,gpu,host,meta}.txt
    summary.md
  experiments/README.md
  experiments/E00N-<slug>/README.md
```

The published summary, `benches/webgpu/<rig>.md`, lives in the repo, not here; see Publish.

## `meta.json`

Written by `run.sh` before the first invocation. Every field is needed to interpret the numbers
later, so it is written even when a run fails.

```json
{
  "rig": "mac-arm64",
  "tag": "base",
  "case_set": "v1",
  "commit": "d907835d",
  "dirty": false,
  "date": "2026-11-17T09:51:13+08:00",
  "dawn_version": "v20260908.214631 / 94c3c9c",
  "os": "Darwin 25.2.0 arm64",
  "gpu": "Apple M2 Ultra",
  "device": "WebGPU",
  "reps": 5,
  "invocations": 3,
  "builds": {
    "bench": "build/bin/llama-bench",
    "profile": "build-prof/bin/llama-bench"
  },
  "models": {
    "Qwen/Qwen3-0.6B-GGUF:Q8_0": {"repo": "Qwen/Qwen3-0.6B-GGUF:Q8_0", "path": "...", "sha256": "...", "bytes": 0}
  },
  "cases": [{"id": "a1", "model": "Qwen/Qwen3-0.6B-GGUF:Q8_0", "p": 512, "n": 0, "d": 0, "role": "..."}],
  "corpus": {"path": "wikitext-2-raw-v1/wiki.test.raw", "sha256": "..."},
  "commands": []
}
```

`builds` records the binary paths, not the cmake line: the cmake line is in the shell history, the
binary path is what actually ran. Put the cmake line in `rigs/<rig>.json` `notes` when it is not the
default from `docs/build.md`.

`dirty: true` means the working tree had uncommitted changes. Such a record can be a `draft` but
never an `accepted` baseline: the numbers cannot be reproduced from the commit.

## `status.json`

```json
{"status": "accepted", "note": "baseline for case_set v1"}
```

| status | meaning | valid base |
|---|---|---|
| `draft` | incomplete, or a run that has not passed the gates | no |
| `accepted` | complete, gates passed, reproducible from the commit | yes |
| `needs-review` | accepted with a caveat that cannot move a measured answer | yes |
| `blocked` | could not run (missing model, no device, build failure) | no |
| `abandoned` | superseded or known bad | no |

Only one record per rig is the current base. The base is the most recent `accepted` (or
`needs-review`) record for that rig; `hill-climb` must not survey a `draft`.

## `summary.md`

Generated by `scripts/summary.py`. Shape:

```markdown
# mac-arm64 20261117-d907835d-base

commit d907835d, case_set v1, dawn v20260908.214631, dirty: no

| id | case | ts run1 | ts run2 | ts run3 | median | noise | ref_ts | ts/ref |
|---|---|---|---|---|---|---|---|---|
| a1 | qwen3-0.6b pp512 | ... | ... | ... | ... | ... | ... | ... |
...

G = <geomean t/s over a1..a6, g1>   G_pp = ...   G_tg = ...
G range over invocations: [min, max]
noise_agg = (max-min)/median

ops: n_supported / n_total cases, W_pp = <us/run>, W_tg = <us/run>
ppl = <value> (corpus <sha8>)
peak rss = <MiB>
load time = <ms>

## profile top shaders
- a2: mul_mat_vec 120.4 ms (61.2%), ...
```

Numbers are read from the record files only. The `ref_ts` column is filled from the `MTL0` runs
when they exist, otherwise `n/a`.

## `ops/cases.md`

```markdown
| op | params | us run1 | us run2 | us run3 | median | noise | w_pp | w_tg | noisy |
|---|---|---|---|---|---|---|---|---|---|
| MUL_MAT | type=q4_0,m=4096,n=512,k=4096 | ... | ... | ... | ... | ... | 0.31 | 0.62 | no |
```

`w_pp` and `w_tg` are the per-token node count from `ops/weights.json` (prefill ubatch and decode
token respectively) divided by the number of cases for that op. `noisy` marks cases below 50 us or
with `noise > 10%`; they are excluded from `W_pp` and `W_tg`.

## Keep decision

Worked shape only, numbers illustrative:

```
baseline G range [100.0, 101.5], median 100.8, noise_agg 1.5%
candidate G range [104.0, 105.2], median 104.6
ranges do not overlap; delta 3.8% > 1.5%  -> keep
```

```
baseline G range [100.0, 103.0], median 101.5, noise_agg 3.0%
candidate G range [102.0, 104.5], median 103.2
ranges overlap                              -> revert, regardless of the point estimate
```

A case-level claim uses the same test on that case with its own `noise`. A guard case that regresses
beyond its `noise` blocks the keep even when `G` improves.

## Publish

`benches/webgpu/<rig>.md` in the repo, regenerated by `scripts/publish.py` from `accepted` records:

```markdown
# WebGPU backend - mac-arm64

Rig: Apple M2 Ultra, Darwin 25.2.0, Dawn v20260908.214631. Case set v1.

| date | commit | tag | G | G_pp | G_tg | delta G |
|---|---|---|---|---|---|---|
| 2026-11-17 | d907835d | base | ... | ... | ... | - |
| ... | ... | E001-... | ... | ... | ... | +x.x% |
```

Rules:

- Only `accepted` and `needs-review` records appear.
- `delta G` is against the previous row on the same rig and the same `case_set`.
- The per-case table for the latest row follows the history table.
- Never hand-edit the file; regenerate it. A hand edit breaks the link between a number and its
  record.

## Immutability

Once `accepted`, a record is read-only. A re-run, a fixed typo in the note, or an extra profile is a
new directory with a new tag (`base-r2`, `E001-r2`). This is what lets a later session trust a
number it did not produce.
